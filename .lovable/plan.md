# Document Studio Desktop Master Upgrade

## Goal
Build one fast document editor that works in the browser and as a secure Windows desktop app, with responsive paper typography, automatic multi-page output, native printing, local folder-backed records, restore/export tools, and the supplied branding.

## Confirmed decisions
- Desktop data root is selected by the user; `D:\DocumentStudio` is offered when available, never hard-required.
- Item rows use unlimited automatic page flow based on measured available space.
- Every launch shows the branded splash for exactly three seconds; the setup wizard follows only when storage has not been initialized.
- The web version keeps a browser-storage fallback. Direct folder sync, silent PDFs, scheduled backups, and installer behavior are desktop-only.

## User experience
1. **Startup and setup**
   - Show “Document Generated by M. Muneeb Ahmed” for exactly three seconds with a restrained fade-out.
   - On first desktop launch, offer “Start Fresh Setup” and “Restore Data from Existing Folder.”
   - Fresh setup asks for a writable data folder and suggests `D:\DocumentStudio` when available.
   - Restore scans an existing Document Studio/Document Generator folder, validates document JSON, categories, folders, and PDFs, then reports imported/skipped records.
   - Launch into a completely blank document after setup; later launches load the saved workspace index without pre-filling the form.

2. **Editor controls and shortcuts**
   - Replace the four document tabs with a “Choose Document” select matching Currency and Paper controls.
   - Add a numeric “Custom Pages” control that sets the minimum page count; content automatically adds more pages when required.
   - Show “Save Document” for new records and reveal “Save As…” only for a loaded/saved record.
   - Keep “Download PDF” and one “Print” action.
   - Add Ctrl/Cmd shortcuts for Print, Save, Save As, New, Undo, Redo, and sidebar Search while leaving standard clipboard/select-all behavior native inside editable fields.

3. **Responsive paper and pagination**
   - Render each physical page as its own fixed-size paper element rather than one tall clipped canvas.
   - Derive typography, spacing, margins, row heights, logo size, and footer size from paper-size scale tokens for A4, A5, Letter, and Legal.
   - Measure rendered row heights and flow rows across pages without a hard item cap.
   - Repeat the table heading and essential document identity on continuation pages; keep totals, terms, payment, signature, and closing block together on the final page.
   - Add “Page X of Y” indicators and clean print page breaks.
   - Export every rendered page as a separate high-resolution PDF page.

4. **Typography and layout**
   - Load Bebas Neue and Montserrat in the document head.
   - Apply the requested font hierarchy through scalable CSS variables instead of fixed page-independent pixels.
   - Keep the supplied 8 Ways Communications logo centered and reduce the logo-to-details gap to 20px.
   - Keep long document titles single-line, amount values unwrapped, totals aligned with the Amount column, and QTY the same width as Unit Price.
   - Preserve the existing #171717 print design, editable tax calculations, payment/signature block, and footer styling.

5. **Document library, folders, and backups**
   - Expand saved-document metadata with category, custom folder, created/updated timestamps, page settings, and storage paths while migrating existing browser records safely.
   - Group sidebar records under relative time headings such as Today, Last Week, and month-based older groups.
   - Add custom folder creation and category filtering; desktop folders mirror the chosen data root physically.
   - Add a selective PDF export dialog with Select All, individual checkboxes, date filters, and a destination-folder picker.
   - Add manual backup export plus a desktop 30-day automatic backup into `<Data Root>/AutoBackups`, with retention metadata and restore compatibility.

6. **Secure desktop storage and PDF workflow**
   - Add a narrow preload bridge for settings, folder selection, document read/write, restore, folder synchronization, PDF writes, selective exports, and backups.
   - Harden Electron with `contextIsolation: true`, `nodeIntegration: false`, `webSecurity: true`, sandboxing where compatible, navigation blocking, and validated IPC payloads/paths.
   - Save JSON records and silent PDF copies under category roots: Invoice, Quotation, DeliveryChallan, and SalesTaxInvoice.
   - “Save Document” updates the active record; “Save As…” creates a distinct copy; “Download PDF” always opens a native save dialog.
   - Use Electron’s print/PDF facilities for desktop background copies and the existing browser PDF path as the web fallback.
   - Trigger `window.print()` for Print/Ctrl+P so the operating system exposes its supported printer, page range, duplex, color, orientation, margin, and paper controls.

7. **Windows packaging and branding**
   - Use the supplied logo in the document and create the favicon from it.
   - Convert the supplied icon image into a proper multi-size Windows `.ico` for Electron Builder.
   - Set Electron Builder NSIS to assisted installation, administrator elevation, per-machine install, and selectable installation directory/drive.
   - Keep writable records outside Program Files in the user-selected data root so the installed app does not require elevation for ordinary saves.
   - Pin Electron packaging dependencies and update the Windows workflow for reproducible NSIS output.

8. **Performance**
   - Split and memoize page/row rendering, stabilize update callbacks, and calculate totals/pagination only when relevant state changes.
   - Load the initial blank editor immediately, then defer saved-library indexing, restore scanning, and backups until after the first render.
   - Debounce persistent index writes and avoid reparsing every document body during sidebar search.
   - Preload the logo and use font-display swap while the splash masks initial font settling.

## Technical structure
- Extend `src/lib/document.ts` for page settings, folder metadata, migration, relative grouping, and serializable undo snapshots.
- Add focused hooks/components for history, shortcuts, splash/setup, pagination, folder/export dialogs, and desktop bridge typing.
- Refactor the current single `DocumentPaper` into page-shell, repeated-header, item-table, and final-summary sections.
- Add `preload.cjs` and Electron main-process modules for validated storage, restore, export, PDF, and backup operations.
- Keep the browser app functional by selecting the desktop adapter only when the secure preload API exists.

## Validation
- Verify blank launch, three-second splash timing, first-run setup/restore, and later-launch behavior.
- Test every document type and paper size with short, long, and oversized rows across multiple pages.
- Test page numbering, repeated headings, totals placement, native print invocation, multi-page PDF export, and clean print-only output.
- Test all shortcuts, undo/redo boundaries, Save versus Save As, search focus, time grouping, folder sync, selective export, and backup restore.
- Check responsive desktop/mobile preview, console errors, and file migration compatibility.
- Validate Electron security settings and Windows build configuration; the hosted preview cannot exercise native filesystem or NSIS dialogs.
